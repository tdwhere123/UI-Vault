# PDF local text deep reader

PDF.js official v5.4.530, release commit 50cc4adac01b8f35cf7d311b9eced150502936fe. Apache-2.0; official distribution JavaScript headers and full license retained. Full original files and adapted source are local; this public preview hosts the runtime and notices, not a source ZIP. Original text-reader shell built around the PDF.js parsing engine, not the upstream official viewer UI. One text-reading scene, not a canvas/page-layout preview. Source is supplied in this local delivery only, not a claim of a public source download.

Document source is original ASCII text and PDF object syntax in src/document.js. It computes offsets/xref and generates Uint8Array locally. No binary/base64 wrapping. Three pages of original assistant-work notes, Helvetica reference, no font files. Text is parsed/extracted by actual PDF.js, not read directly from fixture source. Search index and highlights derive from extracted strings. No OCR, user uploads or arbitrary remote PDFs; no annotations, forms, attachments, script execution, downloads, or external links.

Official fake-worker: WorkerMessageHandler is bundled as UTF-8 JS and assigned to globalThis.pdfjsWorker before getDocument. PDFWorker selects its existing-main-thread-handler branch and LoopbackPort; no new Worker or dynamic worker import executes. isEvalSupported:false, disableFontFace:true, useSystemFonts:true, useWorkerFetch:false, useWasm:false, isOffscreenCanvasSupported:false, isImageDecoderSupported:false, enableXfa:false, stopAtErrors:true. Resource factories explicitly reject CMap/font/WASM requests. No fonts/cMaps/ICC/WASM assets shipped.

Original library retains dormant eval/worker/fetch functionality; literal scan counts are disclosed, not falsely reported zero. In tests Worker, Function, eval, fetch, XMLHttpRequest and WebSocket throw before runtime loading (a saved evaluator is used only by the test harness to start the bundle), and calls remain zero through parsing, navigation, search, invalid-PDF recovery and lifecycle. This is not a browser-level CSP acceptance claim. Keep existing sandbox/CSP, do not broaden it.

Tests use genuine PDF.js parser, real document page/text content and original main-thread worker. JSDOM lacks DOMMatrix, so test defines an empty constructor solely for unused canvas module constant initialization. No canvas rendering is implemented, mocked, or claimed. UI uses escaped text nodes/mark elements. Core data tests are real; pixel/visual acceptance pending.

load/close generation guard prevents old completion winning; page.cleanup after extraction, loadingTask.destroy on replacement/error/close/pagehide. No persistent data. Search/next match changes page and exact extracted-text highlight. Text order/layout is extracted and may differ from original page layout.

Build: npm ci --ignore-scripts (include official esbuild platform optional binary); node build.mjs. In this environment install omitted optional native canvas, so initial build used already-installed official esbuild0.25.5 binary via ESBUILD_BINARY_PATH; this is only a build tool, not runtime. Tests use external JSDOM path specified in source/test.mjs. No binary artifact needs publication.
