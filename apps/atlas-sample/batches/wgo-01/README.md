# WGo.js: One capture, two continuations
Original WGo.js 2.3.1 BasicPlayer reading UI, rules engine, SGF variations, comment panel and native navigation controls. Source: https://github.com/waltheri/wgo.js/tree/34773562647e4e8c9c33f1a29cc3183fd1de90d8/wgo . This is not the npm 3 alpha.
The original fictional 9×9 teaching setup is not a complete recorded game or an AI answer. Black captures the white stone at bb; choose A or B to read two continuations. capCount.black is the number captured by Black. No network play, AI evaluation, user SGF import, editing, upload, download or external-resource loading is offered. Comments and labels are fixed local fixture text.
Original SHELL Canvas stones and official solid-color background configuration replace the optional image-backed rendering. Original controls retain their logic/layout, with clearly substituted Lucide vector icons instead of the mixed Fontello font. Optional external About control and automatic data-attribute initializer are omitted; original coordinates menu remains.
Lifecycle adaptations retain child control references, save the resize callback, clear previous touch-repeat intervals on repeated start, clear on touchend/touchcancel, and dispose listeners/intervals on pagehide. Rules, captures and branch algorithms are unchanged.
Verification: actual original controls and board-coordinate click handler, capture/reversal, two branches, comments, first/last/keyboard, repeated navigation, resized Canvas dimensions, menu close/reopen, touch cancel/repeated start and exit while holding all pass. No eval/Function/network/Worker/Image resource calls occurred in the instrumented test.
Canvas and layout are mocked. Browser pixels, actual mouse/touch targeting and visual geometry have NOT been verified. This is a reading-only local teaching fixture, not a general-purpose user input viewer.
Complete adaptation/original source and build/test evidence are delivered locally under source/; this README does not imply a public source-download service. Public assets and full runtime licenses are enumerated in manifest.json.
