## Verification correction: row-removal settling

The initial test selected the first Remove button after a fixed 70 ms pause. An independent rerun found two row inputs left instead of one. That pause did not guarantee the previous row DOM had left; selecting the still-present old row button again is not an additional data removal.

Release source evidence: packages/survey-core/src/question_matrixdynamic.ts lines 1070–1075 resolves the supplied row with visibleRows.indexOf(value) and immediately returns when index < 0. removeRow (line 1136 onward) resolves a target and calls removeRowAsync; that removes model data before onEndRowRemoving announces the rendered-table change. matrix-rendered-table-host.ts delegates to table.onRemovedRow(row); question_matrixdropdownrendered.ts removes the rendered row from its rows array. React reconciliation/exit DOM can therefore lag model removal. No incorrect extra deletion or core algorithm defect was found. No runtime or original library change was made.

Corrected test uses a 2500 ms bounded condition poll (15 ms polling, not a larger fixed success sleep) for the exact number of actual Deliverable inputs AND detachment of the clicked row button. Each row has a distinct text value. Three immediate clicks on the same original row button must leave precisely rows 2–5. A further detached-button click must remain a no-op. Subsequent removals each await the count/detachment condition and compare every remaining row label, ending at the original one-row minimum and no enabled Remove control. The original count and minimum-limit assertions remain intact.

Five consecutive complete test runs are required and recorded in REPEAT-VERIFICATION.json. These tests validate DOM/state behavior, not CSS timing or visual rendering in a real browser.
