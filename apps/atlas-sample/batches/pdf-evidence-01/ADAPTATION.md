## Original runtime and local scope

Preserves original PdfHighlighter, Highlight, AreaHighlight, Rnd handles, Popup, Tip, MouseSelection, coordinate conversion, selection grouping and annotation layers. PDF.js retains its actual parser, PDFViewer, Canvas page rendering, text layer, page geometry and original same-thread WorkerMessageHandler/LoopbackPort mechanism. No worker URL is fetched and no Worker is created. The viewer is not a newly drawn imitation or a text-only PDF extraction shell.

The local host sidebar, note-list/delete/clear controls, muted theme and fixture are openly authored integration. The original remote/arXiv examples, URL input and document switching are absent. Three pages are generated from explicit, readable ASCII PDF object/stream source, with authored Exodus field-note prose. This is not an existing binary PDF wrapped in base64/text. No original third-party document/media is shipped. The document is fixed, no external file input. Notes remain only in current iframe memory; nothing is saved, sent, downloaded or scheduled.

Select actual page text to open the original Tip and save a comment. Alt+drag selects a rectangular page area and invokes the original local Canvas screenshot method; the original AreaHighlight/Rnd layer supports moving/resizing it. Sidebar buttons use the original scrollTo highlight API. Screenshots, if made by the user in a browser, are newly generated local Canvas data, not packaged binary assets. They are not uploaded. The host does not show a fake screenshot when rendering is unavailable.

## Font/rendering correction, not a visual-review exemption

The existing text-only reader's `disableFontFace:true` option was unsuitable here: with system Helvetica but no font binary, it sent Canvas into missing glyph-path lookup. That failed prototype was rejected. The delivered configuration uses original `useSystemFonts:true` and `disableFontFace:false`, allowing only the fixture's named **local** font resolution and generic fallback, without external fonts. Original PDF.js draws with `"Helvetica",g_d0_sf2,sans-serif`. If local Arial/Helvetica cannot load, the original font loader catches rejection, removes the failed face and retains the generic `sans-serif` fallback. It does not return to the missing glyph-path configuration.

Tests force local FontFace.load rejection and verify all actual Canvas fillText call font strings retain generic fallback, with no font URL/network request. Tests also observe584 original Canvas character drawing calls and15 text spans across3 real parsed pages. Canvas rasterization and font metrics are test substitutes, so this establishes parser/render-command/fallback execution, **not actual pixel appearance or typographic fidelity**. System substitutions can differ from original PDF typography. A browser without Canvas2D gets an explicit unsupported message before loading the document.

## Transparent asset and lifecycle changes

- PDF.js's small binary loading GIF is omitted; the host has plain loading text. Original viewer SVG controls remain percent-encoded readable vector source, under Apache notice. No raster/font binary payload is shipped.
- Original source HTML/CSS/classes and drawing/selection algorithms are retained, with local host styling. The standard original emoji options are system text, not downloaded artwork.
- Disable PDF annotations/form/link handling in the fixed PDFViewer configuration; highlighter's own annotation layers remain. No imported PDF can introduce an external action. Resource factories reject external CMap/standard-font fetches. The fixture contains no embedded font/image/external-link/form data.
- Add generation/disposed guard after original asynchronous viewer-module initialization; use PDFViewer's original abortSignal, setDocument(null) and observer cleanup on unmount.
- Cancel original selection/scale debounces (and handle their cancellation rejections), clear delayed scroll listener reattachment, remove the viewer scroll handler, and unmount separate per-page React roots in a microtask after parent unmount or after PDF.js replaces a detached text-layer container.
- Track/cancel original TipContainer position timers. Track pending original MouseSelection body-mouseup handlers and remove them on unmount; replacement gestures remove previous pending handlers.
- On pagehide unmount React, await document destruction, use try/finally so document-destroy rejection still removes host listeners/root state, and remove remaining module-global window/document handlers through an isolated-iframe listener ledger, restoring previous listener methods. A destruction failure logs a warning, sets disposeStatus=partial and displays an explicit cleanup-failed message; it is not reported as a clean engine shutdown. The injected failure test confirms host cleanup only, not successful engine destruction. This wrapper is scoped to standalone previews, not unrelated shared documents.
- TEST-only hooks for deterministic delayed initialization are eliminated in production.

Default host CSP is unchanged, including its existing data/blob image allowance. No Worker, eval, remote font, media or network permission is added. Generic original PDF.js retains dormant dynamic-import/eval-factory fallback code, but this fixed configuration takes the statically supplied worker handler and disables eval support. Runtime attempt counters, not merely thrown errors, verify zero Worker/Function/eval/network calls on the exercised normal/error/interruption paths. This is not an assertion that every dormant general-purpose PDF.js path is absent.
