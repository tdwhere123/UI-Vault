# React Piano local note keyboard

Original react-piano3.1.3, official npm gitHead d1949ff46795d688fed865888f2c8dac0097596d, https://github.com/kevinsqi/react-piano. MIT Copyright(c)2018 Kevin Qi; full original license and actual runtime dependency licenses included. Original package/dist/maps/CSS preserved locally with hashes and lock/integrity evidence. No upstream source changes. Uses original exported ControlledPiano, KeyboardShortcuts.HOME_ROW, MidiNumbers, active-note diff callbacks, key geometry/style and mouse/touch/keyboard input handling. C4–C5 thirteen semitones, one family. No new fonts, pictures, sound samples or remote resources.

Original visual piano component remains intact; heading, dark surround, explicit audio enable/stop buttons and note readout are an original host. Outer layout horizontal-scrolls on narrow screens rather than deforming original 760px piano. Music sound is simple local WebAudio sine oscillators, NOT a sampled piano, recorded music or AI generation. No microphone/recording/upload/network/storage/clipboard/media element. Default CSP unchanged.

No AudioContext created until explicit enable-button user interaction. resume success checked; unsupported/denied/suspended audio reports silence while original visible keyboard remains usable. 440*2^((MIDI-69)/12) frequency, gain0.045 per note. Original controlled active-note state deduplicates repeated keydown, permits polyphony and invokes noteOn/noteOff callbacks; adapter map also prevents duplicate oscillators. Each stop immediately stops+disconnects oscillator/gain (simple synthesis, click-free acoustic envelope not claimed). Global mouseup/touchend conservatively releases all notes; blur/document-hidden/touchcancel/pointercancel stops all, resets keys and closes AudioContext. Explicit stop and pagehide do the same. Delayed resume success AND rejection paths are generation/context-identity guarded: a late old rejection closes only its own context, never the newer context or status. Partial createGain/connect/start failures stop and disconnect any created oscillator/gain even before registration; then normal emergency shutdown clears registered nodes. No late sound start. Audio becomes opt-in again after blur/hidden/cancel.

Tests run real React Piano code in JSDOM with mocked AudioContext/Oscillator/Gain. Seven branches: normal, missing API, rejected resume, late resume after pagehide, late old rejection after a new context is enabled, createGain failure, oscillator-connect failure. Check no pre-enable context;13 original keys; original key/mouse/touch callback state; duplicate keydown one voice; polyphony/release; exact C4 frequency261.625Hz; lost-keyup blur; touchcancel; page hidden; active unmount/pending resume closure; no microphone/network/eval/Function/Worker attempts. Late rejection regression keeps the new context running and playable; partial-node failures verify oscillators and all created gains disconnected. Actual audio output, device autoplay behavior, touch hardware, sound quality and pixels NOT verified. No claim of audible QA. Source ZIP local only, not hosted download.
